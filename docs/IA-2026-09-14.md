# Information architecture — four surfaces, three verbs (2026-09-14)

> Owner's bar: a 10-year-old can use it; new features slot in without touching the rest; everything feels live.
> Answer to "one page per feature?": **no**. Eight features as eight menu entries is the accountant's UI we are replacing.

## The mental model the user needs (and nothing more)

```
 Sammeln  ──▶  Abgleichen  ──▶  Abschliessen
 (Belege)      (Bank)           (Monat · Quartal · Jahr)
```

Everything the product does is one of these three verbs. The fourth surface, **Heute**, is where the system tells
the user what it needs from them — the only place they *have* to look.

## Surfaces (sidebar has exactly these — today's 9 entries collapse into them)

| Surface | Question it answers | What lives there (today → later) |
|---|---|---|
| **Heute** | "Was muss ich tun?" | inbox of decisions: unsichere Buchungen, unmatched bank lines, überfällige Rechnungen (B-65), "3 neue Belege per E-Mail" (B-69), Steuer zurücklegen (B-71). Empty state = "Alles erledigt 🎉". Replaces Dashboard + Überprüfung + the bell. |
| **Belege** | "Was ist reingekommen?" | drop zone + list (B-64), scanner, **Neu** (B-68 write an invoice). Replaces Rechnungen + Scanner. |
| **Bank** | "Was ist passiert?" | Kontoauszug upload, the Abgleich inbox (phase 3), Buchungen list. Replaces Kontoauszug + Insights. |
| **Abschluss** | "Ist alles sauber?" | three checklists: **Monat** (B-66) · **Quartal/MWST** (B-67) · **Jahr** (B-70 + B-17). Each is a red/green list with one button at the end: *Export nach Banana*. |

Kontenplan, Modell, Lernverlauf, Audit, Einstellungen → one **"Mehr"** group at the bottom (power users, Treuhänder).
The learning is invisible: the user corrects a line, a toast says "gelernt", nothing else.

## Rules that make it 10-year-old simple

1. **One primary action per screen**, top right, in the same place everywhere (Hochladen · Abgleichen · Abschliessen).
2. **Decisions come to the user** (Heute), the user never hunts for them. A row is a decision: accept / fix / skip.
3. **No settings before value.** First run: drop a file → see a result. Kontenplan, VAT, Ollama are defaults.
4. **Say why, not how sure**: "Cembra · wie 12× zuvor" beats "92 %". Confidence stays as a colour, not a number.
5. **Every list is the same list**: same table component, same badge tones, same keyboard (j/k/a/r everywhere).
6. **Wizards for anything with steps** (Abschluss, Rechnung schreiben): one question per step, progress bar, back always works.
7. **German first, plain words**: "Offen", "Bezahlt", "Prüfen" — never "Kreditorenbuchhaltung".

## Rules that make it easy to extend (each feature = one module, drop-in)

```
backend/app/features/<name>/      frontend/src/features/<name>/
  model.py  (tables)                 index.ts   (registers: surface, nav, card on Heute, routes)
  schemas.py                         hooks/ components/ helpers.ts (+ .test.ts)
  service.py (logic, pure where possible)
  router.py  (HTTP only)
  events.py  (what it emits / listens to)
```

- **Registry, not edits**: a feature registers itself (`FEATURES = [documents, abgleich, mwst…]`); `main.py`, the
  sidebar and the Heute inbox iterate the registry. Adding B-67 touches zero existing files.
- **Events, not calls**: `document.created`, `bank_line.imported`, `match.confirmed`, `period.closed`. The Heute inbox,
  the learners and the audit log subscribe. This is also what makes it feel *dynamic* — every surface updates when
  anything happens (SWR keys keyed by event, later SSE from the worker).
- **Feature flags per tenant** (`tenant.features` JSON): ship B-72 Lohn to one tenant first.
- **One table component, one form component, one wizard component** — features compose them, never restyle.
- **Contract tests per feature**: RBAC route walk (exists), tenant isolation walk (exists), plus "every feature has
  an empty / loading / error state" walk.

## Migration path (no big-bang rewrite)

1. Phase 3 Abgleich lands *inside* a new `Bank` surface; Kontoauszug page becomes its first tab.
2. `Heute` replaces Dashboard: cards become inbox rows fed by the same SWR keys (B-16 already unified them).
3. Rechnungen + Scanner merge into `Belege` (scanner is the single-file case of the drop zone).
4. `Abschluss` starts as one page with three tabs; each B-66/67/70 fills one.
5. Sidebar collapses to 4 + Mehr. Old routes redirect for a release.
